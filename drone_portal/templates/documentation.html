Documentation

1. Purpose

This portal is a thin presentation layer over an existing routing engine. The engine is treated strictly as a black box. The website collects inputs, submits them to the engine, and renders the returned Flight Manifest. No statistic, score, route or battery value displayed is fabricated — all are derived from the engine's own output.

2. Input JSON Format

{ "map_size": [Width, Height], "drones": [ {"id": "drone_1", "max_payload": 1.0} ], "deliveries": [ {"id": "d1", "x": 20, "y": 30, "weight": 0.3, "deadline": 200} ], "charging_stations": [ {"x": 50, "y": 50, "slots": 2} ], "no_fly_zones": [ {"shape": "circle", "center": [80,80], "radius": 15, "T_start": 0, "T_end": 150}, {"shape": "rectangle", "corners": [[120,120],[140,160]], "T_start": 50, "T_end": 300} ] }

3. Output Flight Manifest

The engine returns a JSON object with a flight_manifest array. Each entry has a drone_id and a path of timestamped steps. The first step of each path is a PICKUP and the last is a RETURN.

4. Using the Simulation Portal

#Step
1Enter the map size, drones, deliveries, charging stations and No-Fly Zones in the form, OR upload a JSON file.
2Optionally press "Generate JSON from Form" to review the assembled input.
3Press "Run Simulation". The input is validated and sent to the routing engine.
4Inspect the animated route, the simulation log, the Flight Manifest table and the statistics.

5. Validation Rules

  • Map dimensions must be positive numbers.
  • Every drone must have a unique id and a positive max payload.
  • Delivery coordinates must be non-negative; weight and deadline positive.
  • No-Fly Zones must specify a valid shape with the matching geometry fields.
  • Uploaded JSON must be well formed; malformed JSON is rejected with an alert.

6. Local Deployment

pip install -r requirements.txt python app.py # then open http://127.0.0.1:5000/

The routing engine resides at solver/score62.py and is invoked as a subprocess. It is never modified by the portal.
